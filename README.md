# PC資産管理

中小企業の情報システム部門向けPC台帳。Python 3.12の標準ライブラリとSQLiteだけで動きます。Phase 2では、Excelとの受け渡し、日常の検索、変更の追跡、データ保全を追加しました。画面・メッセージは日本語です。

## 起動方法

```bash
python3 app.py
```

Windowsでは `py -3 app.py` でも起動できます。ブラウザーで http://127.0.0.1:8000 を開き、終了はCtrl+C。ポート変更は `python3 app.py --port 8001`。実行ディレクトリによらず、アプリのあるディレクトリを基準にDB等を読み書きします。

初回は `data/assets.sqlite3` を作成し、架空のサンプル5件を投入します。再起動・全件削除後の再投入はしません。既存DBは起動前にバックアップし、元の資産・ID・日時を保持したまま履歴テーブルを追加します。DB削除や手動SQLによる移行は不要です。

認証はありません。同じPCからの小規模な台帳運用を対象とし、待受は `127.0.0.1` に固定しています。社内ネットワークへの公開・複数人での共有運用は次期の対象です。

## 機能と操作

- 登録・編集・削除：管理番号は必須・一意。状態は「使用中／在庫／修理中／貸出中／廃棄」。日付形式と保証期限≧購入日、入力長、不正文字を共通検証し、画面入力はエラー時に保持します。管理番号以外は任意、通常項目は200文字、備考は2000文字までです。
- 検索：管理番号・利用者・機種名の部分一致。`%`・`_` は文字そのものとして検索します。
- 一覧：状態・部署の完全一致で絞り込み、管理番号・部署・利用者・購入日・保証期限・更新日時で昇順／降順。25件ずつ表示し、ページ移動時も条件を保持します。未入力の日付は空文字として並びます。
- 保証警告：一覧で「保証期限切れ」「保証残りN日（0〜90日）」を表示。当日を残り0日とし、未入力・廃棄済みは警告しません。判定日は実行PCのローカル日付です。
- 履歴：資産ごとの「履歴」、または「全変更履歴」で日時・管理番号・操作・項目ごとの変更前後を確認できます。登録・変更・削除・CSV取込を資産と同時に保存し、内容が変わらなければ履歴を増やしません。削除後の履歴も残り、IDは再利用しません。導入前の履歴と操作者名はありません。記録日時はUTCです。
- 競合防止：編集／削除画面を開いた後にその資産が更新された場合は409エラーで拒否します。再読み込みして最新内容を確認してください。

### CSVとExcel

1. 一覧の「絞り込んだ全件をCSV出力」から保存します。現在の検索・絞り込み・並び順が対象で、表示ページにかかわらず全件を出します。
2. 日本語見出し・UTF-8 BOM付き・CRLF改行なので、Excelで日本語が文字化けしない形式です。備考の改行・カンマ・引用符もCSV形式で保存します。
3. 更新用ファイルは見出し・列順を維持し、Excelでは **「CSV UTF-8（コンマ区切り）」** で保存します。通常のShift-JIS CSVは受け付けません。管理番号・シリアル番号の先頭ゼロや長い数字は、Excelのデータ取込で列を文字列に指定して保持してください。購入日・保証期限は `YYYY-MM-DD` にします。
4. 「CSVインポート」でファイルを選択し「一括登録・更新する」を押します。管理番号が既存と完全一致すれば全項目を更新、それ以外は新規登録。空欄は既存値を消去します。管理番号を変更すると別資産になるため、改番は画面編集で行ってください。CSVから削除はできません。
5. 日付・必須・文字数・状態・列数・CSV内の管理番号重複を検証します。1件でもエラーなら **全件変更なし**。行番号（複数行の備考ではレコード末尾の物理行番号）と理由を表示します。修正後はファイルを選び直してください。上限はUTF-8で2MB、見出しを除く1万行（改行を含めた物理行数も1万行まで）です。

数式評価対策として、出力時に `= + - @`、タブ・改行・アポストロフィで始まるセルにアポストロフィを付加します。取込時はこの保護文字を復元します。Excelで見た目・再保存結果を確認してから取り込んでください。

CSVは一括上書きです。画面編集のような版照合は行わないため、直前に出力した台帳を使い、別画面での編集を止めて作業してください。取込前のCSVを保存し、反映後は履歴を確認する運用を想定しています。

### バックアップ・復元

既存DBがある場合、**起動時に1日1回、変更前のDB** を `data/backups/assets-YYYY-MM-DD.sqlite3` へSQLiteのbackup APIで保存します。同日の再起動では上書きせず、日付順で直近7世代を保持します。コピーが失敗した場合は起動を中止します。長期間起動し続ける間の日次コピーは行わないため、毎日起動し直すか停止後に手動保存してください。

復元はアプリを終了し、現状の `data/assets.sqlite3` を別名で退避してから、選んだバックアップを `data/assets.sqlite3` としてコピーし、再起動します。DB全体（資産とその時点までの履歴）が戻り、バックアップ以降の変更は失われます。古いDay 1形式からの復元も起動時に移行します。DBとバックアップはGit対象外です。同じディスク内のコピーなので、PC故障に備える別媒体への保存は運用側で行ってください。

## 設計と構成

HTTPは `http.server`、DBは `sqlite3`、CSVは `csv`、ファイルアップロード解析は `email` を使用し、外部依存はありません。更新はPOST＋CSRFトークン、SQLはパラメーター化、HTMLはエスケープします。

既存の `assets` のスキーマは維持します。管理番号はNOT NULL・UNIQUE、状態はCHECK制約、任意値は空文字。Phase 2で `asset_history`（内部ID、資産ID、操作、変更前後JSON、UTC日時）と資産ID索引を追加し、`PRAGMA user_version=2` を設定します。移行はトランザクション内で実施します。書込みは `BEGIN IMMEDIATE` で直列化し、資産と履歴を同一トランザクションで保存します。

| ファイル | 役割 |
| --- | --- |
| app.py | HTTP処理、共通検証、画面生成、起動 |
| db.py | 初期化・移行、バックアップ、資産・履歴保存 |
| phase2.py | 一覧条件、保証判定、CSV入出力 |
| templates/・static/style.css | 日本語画面・スタイル |
| tests/ | HTTPハンドラー・CSV・移行・バックアップの回帰テスト |
| data/assets.sqlite3 | 実行時DB（Git対象外） |
| data/backups/ | 起動時の世代バックアップ（Git対象外） |
| BRIEF.md・DEVLOG.md | 当初の依頼・設計判断と開発記録 |

一覧の絞り込み・並び替えはメモリ上で処理します。小規模台帳向けで、大量資産ではSQL側のページ分割・索引設計が次の課題です。履歴は改ざん防止監査ログではなく、操作確認用の記録です。

### フウ側での実機確認手順

実データ投入前に、必要に応じてアプリ停止中のDBを退避してください。

1. 通常テストを実行し、`python3 app.py` で起動。既存の5件またはDay 1の登録内容が残ることを確認。
2. `PHASE2-TEST` を登録（部署「検証部署」、保証期限は今日から30日後）。一覧の保証警告と、履歴の登録記録を確認。
3. 検証部署で絞り込み、降順にしてCSV出力。Excelで日本語・備考の改行を確認し、利用者を変更して「CSV UTF-8」で保存。
4. CSVを取り込み、利用者と変更前後の履歴を確認。不正日付の行を加えて取り込み、行番号付きエラーと全件未変更を確認。
5. 同じ資産の編集画面を2タブで開く。一方で保存後、もう一方の保存が409になることを確認。
6. 資産を削除し、全履歴に削除記録が残ることを確認。26件以上の検証データではページ移動と条件保持も確認。
7. 再起動して `data/backups/` の日付付きファイルを確認。停止後、別の検証用コピーのディレクトリでバックアップを復元し、台帳が読めることを確認。
